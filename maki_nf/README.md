# Testing

Test 1 - "Jaccard control test". Parameters are L the genome length and N the number of copies of this genome. Generate a random genome of length L. Create N identical copies of this genome, each with a unique genome name. Create a Newick format phylogeny with a single root, and each genome as a leaf from this root (i.e. a fork phylogeny), and the root is labelled with the name 'd__Bacteria'. Create a corresponding text manifest where each line is a path to a genome. Run this manifest and phylogeny through the Jaccard pipeline. The pipeline should generate a 'jaccard-summary.txt.gz' which is a TSV file with the following columns (no header): 'genome ID1', 'genome ID2', 'match_string', 'jaccard similarity', 'p-value', 'R 95%-CI low', 'R 95%-CI high', 'LCA'. The genome IDs in this output do not match the string genome names, they are unique numerical IDs that can be ignored. It should output that the Jaccard similarity between each pair of genomes is 100%.

Test 2 - "Jaccard simple mutation process". Parameters are L the genome length, N the number of genomes to simulate, and R the mutation rate. Generate a template genome sequence of length L. For each N replicates, generate a new genome sequence by applying a simple mutation process to the template genome and save it to a FASTA file with a unique genome name. The simple mutation process randomly mutates each base of the genome with probability R to a different nucleotide. The most efficient way to simulate this process is to first sample the number of mutations from a Poisson distribution with rate R*L, and then mutate this many bases (positions chosen at random). Again generate a fork phylogeny of these genomes, and run this phylogeny and manifest through the Jaccard pipeline. For every pair of genomes in the output, the calculated 95% confidence interval for mutation rate should contain the mutation rate R (with a ~5% error rate).

Test 3 - "Random Gene Distance control test". This pipeline analyses GFF-format annotated genome sequences. Specifically, for every pair of genomes, it randomly selects a pair of annotated regions, and computes the Jaccard similarity. It is critical that this selection is truly random, and that is what this test is targeting. Similar to the Jaccard control test, the parameters of this test are L the genome length and N the number of copies of this genome, with an additional parameter A the average annotation size. Generate a random template genome of length L. Cover the genome sequence in sequential, non-overlapping GFF annotations where the size of annotations has a Poisson distribution with mean A, and annotations are balanced between forward and reverse strands. Each annotation should refer to the accession of the genome sequence, and have an attribute with the form 'Parent=gene-[GENEID]' where GENEID is an alphanumeric string unique to each location on the genome. This is important because while we will generate N identical copies of this genome, the GENEID represents the same genomic location between each sequence. The disk format of such random annotated genomes is GFF3 format, where the first part of the file contains the GFF3 format annotations, followed by a '##FASTA' block with the FASTA-format genome sequence. Generate N identical copies of this annotated genome, where each copy has a unique genome name (and unique contig accessions). As in the Jaccard control test, create a fork phylogeny of these genomes and a manifest outlining their locations. We also need a cluster file to run the Random Gene Distance pipeline. Annotations with the same GENEID should be in the same cluster, and have the format '[ACCESSION]-gene-[GENEID]', where ACCESSION is the accession of the FASTA format contig. Create a cluster file where each line has the format '[REPRESENTATIVE]\t[MEMBER]' where REPRESENTATIVE is the cluster ID of the first sequence, and every occurrence of GENEID among the genomes is represented by a MEMBER. For example, say we have three genomes 'genomeA', 'genomeB' and 'genomeC', and each of these genomes has two annotations corresponding to two genes 'geneA' and 'geneB'. The cluster file should look like this:
genomeA-geneA\tgenomeA-geneA
genomeA-geneA\tgenomeB-geneA
genomeA-geneA\tgenomeC-geneA
genomeA-geneB\tgenomeA-geneB
genomeA-geneB\tgenomeB-geneB
genomeA-geneB\tgenomeC-geneB
Run this manifest, phylogeny, and cluster file through the Random Gene Distance pipeline. The pipeline should generate a 'feature-table.txt.gz' which is a TSV file with the following columns (no header): 'genome ID1', 'genome ID2', 'match_string', 'jaccard similarity', 'p-value', 'R 95%-CI low', 'R 95%-CI high', 'LCA', 'cluster ID'. When the same region has been sampled between genomes, the 'cluster ID' column will contain the representative cluster ID of that region, otherwise it will contain 'NA'. The output should show that random regions have been sampled, and that when the same gene has been sampled between genomes, the jaccard similarity should be 100%.

Test 4 - Random Gene Distance mutation process. This is similar to the Random Gene Distance control test, but now we introduce a mutation rate for each GENEID. This test has the same parameters as the Random Gene Distance control test. When sampling each annotation of the template genome sequence, sample an additional mutation rate parameter uniformly from the range (inclusive) [0.05, 0.6]. To generate the N genomes, rather than creating an identical copy of the template, create the genome one annotated segment at a time by running a simple mutation process on the template region to generate the new region. The new region should still have the same GENEID as the template sequence, to show that they are related. Use the efficient method I outlined above for the simple mutation process. When writing the genome sequences to disk, save the sampled mutation rate for each GENEID as a GFF attribute, alongside the Parent attribute. Generate a manifest, fork phylogeny and cluster file in the same manner as the Random Gene Distance control test, and run it through the Random Gene Distance pipeline. The output should again show that random regions have been sampled, and when the same gene has been sampled between different genomes, the mutation rate of the gene should be captured within the R 95% confidence interval.

Test 5 - K-mer Prevalence control test. The setup and parameters for this test are identical to the Jaccard control test, except now this data is run through the K-mer Prevalence pipeline. The output of this pipeline is a file 'cooc.kmers.lca1.txt.gz' which is a TSV file containing the following columns (no header): 'signature prevalence', 'node size', 'signature size', 'LCA'. Since the input genomes are identical, the 'signature prevalence' value should match the 'node size' value for every line of this output.

Test 6 - K-mer Prevalence random sequences. The setup and parameters of this test are identical to the Jaccard simple mutation process test, except now this data is run through the K-mer Prevalence pipeline. This test does not expect any specific values, but will be used to explore the distribution of output values for different sets of input test parameters.
